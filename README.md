# Rollo USB Print Fix

A macOS utility for USB Rollo printers that print incomplete labels. It keeps the official Rollo driver and adjusts how print data is sent to the printer.

## Requirements

- macOS 13 or newer, on Apple Silicon or Intel.
- A USB-connected Rollo printer using the official Rollo USB macOS driver.
- An administrator account for installation and removal.

Wi-Fi, AirPrint and remote/shared printer queues are not supported. Install the official driver from [Rollo's setup page](https://www.rollo.com/setup/) and add your printer in **System Settings → Printers & Scanners** before using this tool.

## Install

1. Download the Setup ZIP from [Releases](https://github.com/gabeosx/rollo-usb-print-fix/releases) and extract it.
2. Finish or cancel pending print jobs in **Print Center**.
3. Open **Rollo USB Print Fix**. It lists your compatible printers and any setup problems.
4. Choose **Install…** and follow macOS Installer. Authorize the installation when prompted.

The installer applies to all compatible USB Rollo printers on the Mac, including renamed printers. It keeps printer names, paper, speed and darkness settings, and selects 203 dpi when available. Printers that were paused remain paused. No jobs are canceled and no labels are printed during setup.

## Print

Keep choosing your existing Rollo printer in your usual app. For standard shipping labels, use:

- **Paper:** 4×6 inches
- **Orientation:** portrait
- **Scale:** 100%
- **Resolution:** 203 dpi
- **Preset:** Default Settings, or a saved preset using those settings

Resume a paused printer in Print Center when ready. Print one label to check the result before sending a batch. A typical 4×6 label takes about five additional seconds to transfer.

The fix works locally with the existing print queue. It requires no account, background service or external data upload.

## Remove

Finish or cancel pending jobs, open **Rollo USB Print Fix**, and choose **Remove…**. The standalone removal package does the same thing.

Removal restores the original Rollo converter and keeps the official driver installed. Current paper, speed and darkness settings are preserved. The earlier default resolution is restored if it has not since been changed. The management tool and local backups remain available for recovery.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| No compatible printer found | Install the official USB driver, connect by USB, and add the printer in Printers & Scanners. |
| Setup reports pending jobs | Finish or cancel them in Print Center, then choose Check again. |
| Label is tiny, cropped or misaligned | Check paper size, orientation, scaling and the saved preset in the printing app. |
| Printer remains paused after interrupted setup | Stop sending labels and ask an administrator to follow the [recovery guide](docs/ADMINISTRATORS.md#recover-interrupted-setup). |
| Printer or driver was reinstalled | Open this tool and install the fix again if needed. |

The fix changes USB print delivery. Mechanical feeding problems, label-stock calibration and incorrect document layout need separate attention.

<details>
<summary><strong>Technical background: how the fix works and what the evidence shows</strong></summary>

A complete label can reach the USB printing stage and still produce an incomplete print. This utility changes the delivery timing while preserving the label data generated by the official Rollo driver.

```mermaid
flowchart LR
    A[App or PDF] --> B[macOS printing]
    B --> C[Official Rollo converter]
    C --> D[Paced output]
    D --> E[macOS USB backend]
    E --> F[Printer]
```

The [pacing filter](Sources/filter.c) launches the installed Rollo converter with the original input and print options. It uses a read-only CUPS side-channel query to wait for backend readiness, then forwards the converter's output unchanged in writes of at most **512 bytes**, with **20 milliseconds between chunks**. These are software write sizes, not USB packet boundaries. The macOS USB backend remains responsible for communicating with the printer. Converter errors, output failures and cancellation are reported back to macOS.

For the 126,856-byte label used in the controlled test, pacing adds about five seconds of transfer time. Paper size, orientation and scaling still need to be correct in the printing app.

**The diagnostic evidence points to delivery timing.** Binary inspection with [REA](https://github.com/morluto/rea), offline conversion tests and CUPS job captures made it possible to examine the stages separately. REA helped inspect the converter's architectures, dependencies and available function symbols; the decisive evidence came from comparing and replaying its output.

| Check | Observation | What it establishes |
| --- | --- | --- |
| Compare Firefox and native PDF output | Both produced the same complete 126,856-byte printer stream. | The missing label content was present before USB delivery. |
| Change delivery while holding content constant | Ordinary delivery used writes as large as 8,192 bytes and produced an incomplete label. Replaying the same bytes with 512-byte chunks and 20 ms spacing produced a full label. | Changing the delivery pattern changed the physical result. |
| Print through the normal Firefox Print button with pacing installed | The complete label printed correctly; logs recorded 248 writes, each at most 512 bytes, totaling 126,856 bytes. | The fix worked through the normal application print path, beyond the controlled replay. |

Firefox was using the macOS print pipeline. Its association with the failure did not mean that it bypassed system printing. Likewise, successful host writes and a completed print job did not establish that the physical label was complete.

These observations support a timing or buffering problem somewhere in the USB delivery path. They do **not** isolate the underlying defect to printer firmware, the USB hub, the driver or the macOS backend. The physical confirmation covered a USB Rollo X1038 connected through a hub to an Apple Silicon Mac, running macOS 27.0.1 with Rollo driver package 1.8.3 and PPD 1.8.1. Compatibility and long-term reliability on other configurations require physical testing.

**Resolution is a separate consideration.** Offline tests of the vendor converter's 600 dpi path produced an extra solid black final row; the 203 dpi path avoided that artifact. This is why installation selects 203 dpi when available. That rendering artifact alone did not explain the incomplete-content failure.

**Verification covers both printing behavior and safe installation.** Synthetic filter tests check byte preservation, pacing, backend readiness, cancellation and failure propagation. Installer tests cover settings preservation, multiple and renamed queues, arriving jobs, interrupted setup and rollback conflicts. Installation, removal and reinstallation on the test Mac verified restoration of the original converter and preservation of queue settings and states.

The [release workflow](docs/RELEASE.md) checks package contents, signatures, notarization tickets, embedded installer copies and download checksums before publishing. Those checks establish distribution integrity and trust; they do not replace physical printing tests on a particular setup.

The distributed code contains the pacing filter and setup tools. The proprietary Rollo converter remains a separately installed dependency and is not modified or bundled with this project. For implementation details and test commands, see the [development guide](docs/DEVELOPMENT.md).
